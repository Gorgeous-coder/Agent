# 备忘技能

## 重要认知（必须先读）

- 调用本技能（personal-note 工具）返回的内容，只是"技能使用说明书"，绝不是用户的备忘数据！
- 备忘数据只存在于磁盘上的 {备忘目录}/{userId}.md 文件里，只有通过 Read 工具读取才能拿到。
- 禁止根据 personal-note 工具返回的说明书内容，直接判断"备忘录里有什么"或"没有内容"。

## 触发场景

- 记录：用户说"记一下 xxx"、"请记 xxx"、"记录一下 xxx"
- 查看：用户说"我的备忘"、"看看备忘"、"备忘录里有什么"
- 清空：用户说"清空备忘"、"删除所有备忘"

## 执行步骤（必须按场景执行完，禁止中途结束）

1. 先判断用户意图是 记录 / 查看 / 清空

2. 记录时，必须连续执行：
   a. 调用 Read 读取 {备忘目录}/{userId}.md（若文件不存在 Read 会返回错误，可跳过追加，直接走 b）
   b. 调用 Write 写入"已有内容 + 新增内容"到 {备忘目录}/{userId}.md
   c. 回复："已记下：{新内容}"

3. 查看时，必须连续执行：
   a. 调用 Read 读取 {备忘目录}/{userId}.md
   b. 把 Read 返回的文件内容原样整理回复给用户
   c. 若 Read 返回"文件不存在/错误"，回复"你还没有备忘"

4. 清空时，必须连续执行：
   a. 调用 Write 写入空内容到 {备忘目录}/{userId}.md
   b. 回复："已清空全部备忘"

5. 未调用 Read / Write 工具之前，禁止回复任何关于备忘内容的结果。

## 硬性要求（必须遵守）

- 加载本技能后，必须立即调用 Read / Write 工具完成实际操作，严禁反问用户、严禁只汇报目录信息
- 记录时，要记的内容就是用户消息中"记一下/请记/记录一下"等触发词之后的文字，直接提取并写入，不得再次询问
- 查看时，必须调用 Read 工具读取文件后再回复，严禁未读文件就回答"没有内容"

## 文件约定

- 每个用户一个备忘文件，路径为系统提示"备忘目录"下的 {userId}.md，即 {备忘目录}/{userId}.md
- {userId} 必须用系统提示中"当前用户ID:"后面的具体值替换（例如 当前用户ID: test-user → test-user.md），不要保留花括号占位符
- 使用 FileSystemTools 的 Read 工具读取、Write 工具写入
- 追加时：先 Read 读取现有内容，再 Write 写入"旧内容 + 新内容"
- 文件不存在时 Read 会返回错误，此时直接 Write 创建即可
