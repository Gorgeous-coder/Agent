# 2026-08-20 工作日志

## 项目：wechat-ilink-sdk-java

### 1. 新增 Translator 翻译工具类（仿 Weather 模式）
- 用户要求加一个工具类，风格与 Weather 一致（独立类 + tryHandle 一站式处理），选择了翻译器
- 新建 `bot/Translator.java`：
  - 翻译 API：**MyMemory**（`https://api.mymemory.translated.net/get?q=..&langpair=zh|en`，免费无 key；Google translate.googleapis.com 和有道 fanyi 实测被墙/超时，放弃）
  - `tryHandle(text)`：识别翻译意图（翻译/译成/译一下/怎么说/怎么讲/怎么读）→ 提取原文（4 个正则：把xxx翻译成yyy / 翻译xxx / xxx怎么说 / xxx翻译）→ 目标语言检测（显式语言词优先，否则中文→en、非中文→zh）→ 调 API → 返回 "🔤原文/🌐译文/（方向）"
  - 支持中英日韩法德西俄泰意葡阿越 13 种语言
  - 单次限 500 字符；提取原文时"翻译成/译成"必须在"翻译"前面匹配，避免"成"字残留
- BotMain 接入：字段 translator、构造初始化、handleText/handleVoice 在天气分支后加翻译分支（语音翻译走 tryVoiceReply TTS）、stop() 关闭
- 测试用例（8 个）全部通过：中英互译、把xx翻译成yyy、xx怎么说、日语、非翻译意图返回 null
- 已知局限：源语言只检测中/英（非中英原文会被当英文），MyMemory 免费版长句翻译质量一般
- 编译通过 ✅

### 2. 解决 IDEA 27 个编译错误（实际为缓存问题）+ 新增 Calculator 计算工具类
- 用户反馈 IDEA 报 27 个错误（Cannot resolve symbol 'Translator' 等），担心翻译跑不起来
- **真相**：javac 直接编译 0 错误，Translator.class、BotMain.class 都是最新的——**问题只是 IDEA 增量编译缓存没识别新加的 Translator 文件**
- 解决：全量 javac 编译所有 .java 文件确保 target/classes 干净；让用户在 IDEA 里 **Build → Rebuild Project** 或 **File → Invalidate Caches**

- 新建 `bot/Calculator.java`（用户要求"做一个计算类"）：
  - 纯 JDK 实现，不依赖任何外部 JS 引擎（JDK 21 Nashorn 已被移除，ScriptEngine 返回 null）
  - `tryHandle(text)`：识别计算意图（含数字+运算符/算术词）→ 中文→符号 normalize → 提取算式 → **递归下降 Parser 求值**
  - 支持：四则（+ - * /）、括号、小数、负号；中文运算符（加/减/乘/除/乘以/除以/×/÷）；幂（x 的 N 次方 / x 的平方 / x 的立方 → x^N / x^2 / x^3）；根（开方/平方根 → x^0.5）
  - Parser：parseExpr(parseTerm(parseFactor(parseNumber))) 递归下降 + `maybePower` 处理 ^
  - **踩坑**：第一版 javadoc 注释里写了 `"*/"` 字符串字面量，恰好关闭了 /* */ 注释块，导致后续代码被当作实际 Java 编译——错误是"未结束的字符串"。修复：注释里改用描述性文字代替 `"*/` 字面量
  - **踩坑**：第一版 parseNumber 没调 maybePower，2^8 这种算式解析失败。修复：parseNumber 末尾调用 maybePower
  - 测试 12 个用例全过：1+2*3=7、100 除以 4=25、(2+3)*5=25、2 的 8 次方=256、16 的平方根=4、5 的平方=25、9 开方=3、-5+3=-2、(1+2)*(3+4)=21、2^10=1024；非算式（你好/今天天气不错）→ null
- BotMain 接入：字段 calculator、构造初始化、handleText/handleVoice 在翻译分支后加计算分支（语音计算走 tryVoiceReply TTS）、stop() 关闭
- 全量编译（src/main/java 下所有 .java）通过 ✅

### 3. 修复 IDEA 编译错误的根本原因：JDK 版本不匹配
- 用户又发来截图，IDEA 报 27+ 错误（全部 "无法访问 com.github.wechat.ilink.sdk.*"），build failed，提示 "无效的目标发行版 65.0, 应为 61.0"
- **真正的根本原因**（之前以为是缓存问题，实际更深）：
  - pom.xml 配置 `maven.compiler.source>8</source> <target>8</target>`（要求 Java 8 字节码）
  - IDEA 模块默认用 JDK 21 编译（major 65）
  - 我之前用 JDK 21 的 javac 编译，生成 class 是 major 65（=JDK 21）
  - 编译能过（javac 自己不在意），但**IDEA 模块加载时检查字节码兼容性，发现 class 是 65 但项目要求 8，且 SDK 是从外部 jar 找**——于是报"无法访问"
- **真实情况**：pom.xml 里没声明 `wechat-ilink-sdk` 依赖，所以 IDEA 期望从 jar 找 SDK 类；找不到就报无法访问
- **根本修复**：
  1. 把 pom.xml 的 source/target 从 8 改成 17（与 IDEA 默认匹配）
  2. 用 `D:\Java\jdk17\bin\javac` 全量重新编译所有 .java 文件（生成 major 61 class，与 pom.xml 一致，与 IDEA 一致）
  3. 让用户在 IDEA 里 **File → Invalidate Caches → Invalidate and Restart**（或者 Maven → Reload project）
- 端到端验证：用 JDK 17 编译 Weather / Translator / Calculator 三个工具类，全部正常工作（翻译/计算/天气都能正确分流处理）
- 教训：**自包含项目（既是 SDK 又是应用）的版本一致性是个隐患**，pom.xml 的 source/target 必须与 IDEA 的 JDK 版本对齐
